# Jev 模块兼容性审计

这份文档定义各模块的职责，避免“同一个概念多个模块各说一套”。

## 权威分层

| 层 | 权威来源 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 当前场景 | Jev 当前可见聊天 | 判断语气、意图、互惠、趋势、唯一主动作 | 被旧画像覆盖当前事实 |
| 关系策略 | 狗头军师 | 给 best_action 提供执行方式、互惠/边界/表达依据 | 自己再产生第二套动作 |
| M3 / PUA | 教学投影 | 显示 A1~S3、IOI/IOD、术语解释 | 反向控制回复；强制阶段顺序 |
| 长期关系 | 分层历史分析方法 | 关系状态、趋势、重要事件、时间窗口 | 用单条消息直接写长期结论 |
| 人格 | WeChat Persona schema | Big Five / 30 facets 等批量人格结构 | 混进单条实时关系判断 |
| 记忆 | O-Mem 方法 | 原始资料、事件、Persona 分层与相关检索 | 原始资料直接变成策略事实 |
| Persona 证据 | PersonaMem-v3 方法 | 多证据、矛盾、reinforced/contradicted/faded | 相邻主题因为“差不多”就合并 |
| Blaniel | schema 参考 | 借人格/依恋字段结构 | 用 AI 角色 BPD/NPD/Yandere 模拟器诊断真人 |
| BigFive-LLM-Predictor | 评测参考 | 理解其 BFI 实验结构 | 当作真人聊天人格测评器 |
| Kink Directory / KList / Atlas | 分类词典 | 统一术语、角色、长尾偏好 | 词典命中就当作人物事实 |
| KinkXKnow | 显式问卷 | 对用户明确填写的问卷答案评分 | 用聊天推测冒充问卷答案 |

## 实时链

当前消息 -> 当前判断 -> best_action（唯一主动作） -> 狗头军师相关依据 -> 起草/排序

长期人物画像和互动攻略只进入起草参考，不进入当前状态判断。

## 关系状态、趋势、任务、M3

它们现在是四个不同概念：

- **relationship_stage**：当前关系状态，例如双向浪漫兴趣、约会中、稳定关系。
- **interaction_trend**：最近在升温、平稳、降温还是波动。
- **interaction_task**：当前功能任务，例如观察互惠、建立连接、建立信任、确认下一步。
- **m3_phase**：经典 M3 教学投影，只用来帮助理解原体系。

M3 可以按当前证据跨级，但不会驱动回复动作。

## 亲密话题

Jev 的 0~8 现在只叫“亲密话题深度”，不是关系阶段、不是 M3、不是现实行为进度。

话题兴趣、幻想、现实意愿、实际经历、明确边界继续分开保存。

非恋爱人物默认关闭亲密/性偏好分析；人物工作台可对单次输入显式打开。

## 数据来源

微信、QQ、抖音、Telegram、线下观察等都只是 source。人物主键、记忆、策略、Markdown 导出与平台无关。
