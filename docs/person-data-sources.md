# 人物数据源架构

Jev 的人物分析不再以微信为前提。

## 统一入口

所有资料最终都进入平台无关的人物档案：

- 手工观察
- 对方明确说过的话
- 粘贴聊天
- 平台导入记录
- 微信历史
- 抖音 / QQ / Telegram / 小红书 / 微博等其它平台
- 线下观察

原始资料先保存，再由人物分析 Agent 提取结构化画像。平台只是来源元数据，不是人物主键。

## 当前能力

### 已支持

- 没有任何聊天记录时直接新建人物
- 和人物分析 Agent 连续对话
- 输入自己的观察
- 输入“对方明确说过”的原话
- 粘贴任意平台聊天
- 标记资料来自微信、抖音、QQ、Telegram、小红书、微博、线下或其它来源
- 生成长期人物画像
- 生成互动攻略
- 导出当前人物完整 Markdown
- 导出全部人物 Markdown

### 当前仍是平台专用的部分

实时自动采集目前仍只有微信 Windows OCR 实现。

这不影响人物分析层。未来如果增加抖音、QQ、Telegram 的实时采集，只实现
core/sources/provider.py 中的平台适配器接口，人物记忆、攻略、导出和 Agent 层不需要重写。

## 数据分层

原始资料 -> source_items

人物分析对话 -> analysis_dialogue

人物事实/推测 -> memories

关系趋势 -> relationship_snapshots

亲密与性偏好 -> intimacy_preferences

互动攻略 -> strategy_profiles

## 重要规则

- 用户自己的观察默认只是推测依据，不自动变成“对方明确事实”。
- 对方原话和真实聊天里的直接表达才允许形成 explicit。
- 幻想、话题兴趣、现实意愿、实际经历、明确边界分开保存。
- 互动攻略是策略，不反向污染人物事实。
